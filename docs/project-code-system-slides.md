# Project Code System — How Codes Are Made & Integrated

*Source material for a slide deck. Focus: how project codes are created in the new
Quote Tool and how that differs from the old Salesforce/Databricks system, where a
code was generated for every account + opportunity.*

---

## The change in one line

- **Old:** *every* Salesforce account + opportunity automatically got a project code, generated by a Databricks pipeline — whether or not anyone was working on it.
- **New:** project codes are created **manually, on demand**, inside the Quote Tool. You still pick a real Salesforce **account + opportunity** (or type a new one), but a code is only minted when someone actually needs one.

Push/automatic-for-everything → **pull/on-demand-when-needed**.

---

## The OLD system (Databricks, automatic)

- Salesforce data syncs into Databricks (via Fivetran) as `salesforce.account` / `salesforce.opportunity`.
- A Databricks notebook (the "CodeGen" logic) then:
  - Assigned a **4-letter code** to every account (e.g., Toyota → `TOYT`).
  - Built a **project code for every opportunity** = account letters + a **global running index** → e.g., `TOYT1148`.
  - Stored them all in `etl.sf_opportunities`.
- **Result:** a code existed for **every** account + opportunity in Salesforce, automatically.
- Collisions on the 4 letters were resolved by **swapping in other letters** (the "random-looking" 3-letter variants).
- Codes lived in Databricks and were read by dashboards / other tools.

**Downsides:** codes for things nobody was quoting (clutter); hard-to-read collision variants; a global index number that doesn't tell you "customer's project #2."

---

## The NEW system (Quote Tool, manual)

- Codes are **minted one at a time, by a person, when they need one** — not swept from Salesforce.
- You choose **Customer work** or **Internal Machina work**.
  - **Customer:** search + select a live Salesforce **Account**, then **Opportunity** — or type a brand-new one not yet in Salesforce.
  - **Internal:** pick a **team** + a **project name**.
- The tool generates a **clean code**: 4-letter compaction of the name + an incrementing number.
  - Customer: `TOYT001`, `TOYT002`… (no random letters — uniqueness comes from the number).
  - Internal: same, with a leading **M** → `MPROD001` (Product), `MSOFT001` (Software).
- **One code per account + opportunity:** if that opportunity already has a code, the tool **shows the existing code** and refuses to make a duplicate.

---

## The key difference (the headline slide)

| | Old system | New system |
|---|---|---|
| **Who makes the code** | Databricks pipeline, automatically | A person, manually in the tool |
| **When** | For every account + opportunity, always | Only when someone needs a code |
| **Coverage** | Every opportunity has a code | Only worked-on ones do (blank is fine) |
| **Anchored to Salesforce?** | Yes | **Yes — still pick a real SF account + opportunity** |
| **Format** | `TOYT1148` (letters + global index; letter-swaps on collisions) | `TOYT001` / `MPROD001` (letters + clean counter) |
| **Lives in** | Databricks tables | The Quote Tool |

**The point to land:** we didn't lose the Salesforce link — you still select the account + opportunity. We just stopped auto-generating a code for *every* one of them and made it a deliberate, manual step.

---

## The workflow (step-by-step)

1. **Project Code → Generate.**
2. **Customer work** or **Internal Machina work.**
3. **Customer:** search/select the Salesforce **Account**, then the **Opportunity** (pulled live from Salesforce) — or type a new one.
   **Internal:** pick the **team** and a **project name**.
4. **Generate** → a unique code is created.
   - If that account + opportunity already has a code, it shows the **existing** code instead (no duplicate).
5. **Copy** the code and use it.

---

## Managing codes (List, status, history)

- **Project Code List:** searchable and filterable — by status, and field-by-field (account, opportunity, code, creator).
- **Statuses:**
  - Customer codes: Discovery / Completed / Closed Won / Closed Lost.
  - Internal codes: Internal / Completed.
  - Default view = **Open** (active work).
- **History:** every status / customer / project-name change is logged with **who and when**. The **code itself never changes.**

---

## How it integrates with quotes

- Building a quote starts by **selecting its Project Code** (search by code, customer, or opportunity). That auto-fills the **Account Name** and **Project Name**; you then give the **Quote** its own name.
- The home screen shows each quote's **account : project** context and a per-quote status (**Open / Closed Won / Not Used**).
- **Multiple quotes can share one project code** — e.g., four quotes under one project; the customer signs two (Closed Won) and the rest are marked Not Used.

---

## The Salesforce list (reference)

- The tool shows the **live Salesforce accounts + opportunities** (from Databricks, refreshed roughly hourly), with a **Project Code column** so you can see which opportunities already have a code — and which don't (shown as "—", which is expected).

---

## Data & dependency (what we still rely on)

- The list was **seeded once** from the old Databricks codes (preserves history + guarantees no collisions).
- After that it **diverges**: new codes come **only** from the tool; new codes appearing in the old Databricks list are **ignored**.
- The account/opportunity **pickers still read live Salesforce** (through Databricks/Fivetran) — that dependency stays. The **code registry itself now lives in the Quote Tool.**
